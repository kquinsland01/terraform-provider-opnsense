# opnsense_quagga_bgp_global (Resource)

This existing singleton retains its state address and does not remove appliance
settings on destroy. Installed os-frr metadata and read-only model capabilities are
validated independently of core firmware before writes. Read permissions for package
information and the BGP neighbor template are required. Legacy live proof remains
unverified; future/contradictory capabilities fail closed.

For fresh activation, configure BGP while General remains disabled, then enable
General, then create active peers. FRR service reconfigure is a soft reload and
does not start a newly added daemon on an already running service; that transition
may require a separately reviewed restart. It also does not activate PF rules.
Confirmed saved settings survive reload/read-back failure with private pending
activation; refresh recovers without replaying an unchanged saved update.

Use explicit approved-prefix policies and independently verify effective routing.
This compatibility subgate is not full advanced BGP parity, a provider release,
OpenTofu proof, or production adoption authorization.
