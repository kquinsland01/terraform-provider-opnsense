## Activation boundaries

The plugin's API service reconfigure is a soft reload (`status=ok`). On a fresh
appliance, enabling General before BGP starts watchfrr without bgpd; subsequently
adding BGP to the daemon set does not make soft reload start bgpd. The isolated
fixture therefore configures BGP while General is disabled, then enables General.
This does not introduce provider-wide restart behavior or prove active-appliance
migration/restart behavior.

Automatic broad inet46 TCP/179 PF rules are generated by the plugin but FRR service
reconfigure does not reload PF. The harness explicitly requests the parent-provided
lab filter-reload operation and records its actor as lab-only, not provider behavior.
When General is disabled, the stop path does not regenerate inactive `frr.conf`;
a host-only exact-VM/TLS-guarded disabled template sync restores that file after
verified API rollback. No SSH key is mounted inside containers and no raw XML is
edited by the provider.
